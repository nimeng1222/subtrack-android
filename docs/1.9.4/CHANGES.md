# 1.9.4：AI「能列模型、一发消息就 403」的修复（2026-10-31 / 61）

## 现象

配置好 AI（模型列表能正常获取），在 AI 页发消息报 `服务请求失败 HTTP 403`。

## 三个最可能的原因，与这次的处理

| 原因 | 为什么会这样 | 现在 |
| --- | --- | --- |
| 服务地址只填到 `…/v1` | `/v1/models` 能取到，但对话被 POST 到 `/v1` 本身，服务端拒绝 | 发送时自动补成 `…/v1/chat/completions`（也支持 `…/v1beta/openai`）；不改已保存的值，不动密钥绑定。设置页会直接显示「发送时会自动补成 …」 |
| 模型不支持 tool calling | 有的服务不回 400 说明，而是直接 403 | 第一轮收到 403（或 400 且提到 tools/function）时，去掉 `tools` / `tool_choice` 再试一次；系统提示词同步切换成「看不到台账、不能联网」，回答里不会假装查过网页 |
| 其他 403（Key 无权限、地区/WAF 拦截） | 以前只显示「HTTP 403」，没有服务端原话 | 错误气泡带上服务端返回的原文：JSON 取 `error.message`，HTML 去标签压成一行，最长 240 字；并多一个「设置」入口 |

另外两处兼容性调整：

- 请求体显式带 `stream: false`（有的网关缺省会按流式返回，客户端只收到半截 JSON 或直接拒绝）；
- 请求带 `User-Agent: SubTrack-Android/<版本>`。

## 新功能：设置页「测试对话」

「设置 → 联网与 AI → 测试对话（发一条最小请求）」：用已保存的地址、Key、模型发一条 16 token 的请求，
直接告诉你是「对话接口可用」还是服务端原话。不用回 AI 页试错，也不会把台账发出去。

只使用**已保存**的配置；有未保存的草稿时会提示先保存（沿用既有规则）。

## 验证

- JVM **472 / 472**（新增：地址归一化 5 条、无 tools 请求体、错误响应压缩、降级判断）。
- 设备严格门禁 **173 / 173**（新增一条：fixture 对带 tools 的请求回 403，应用自动降级并给出回答）。
- Lint **0 error / 33 warning**。
- 实机（截图在本目录 `screenshots/`）：
  - `01` 地址填 `…/v1`，设置页提示自动补全；
  - `02` 「测试对话」返回「对话接口可用」；
  - `03` 正常工具链路：AI 打开官网定价页并回答 `$17.99`；
  - `04` 服务对 tools 回 403：自动降级为普通对话，正常显示回答、无错误气泡；
  - `05` 服务返回 403 + 原因：气泡显示「HTTP 403：这个 Key 没有该模型的对话权限」，旁边有「设置」。

## 兼容与迁移

| 项 | 变化 | 老数据 |
| --- | --- | --- |
| 设置存储 | 无新增字段 | 直接可用 |
| 已保存的服务地址 | 不改写；只在发送时补全 | 原来能用的地址行为不变（已是 `/chat/completions` 就原样使用） |
| 密钥 | 仍绑定在已保存的地址上 | 不需要重新填 |
| 版本 | 1.9.4 / 61（Debug 签名 `df3cced0…`） | 可覆盖 1.9.0–1.9.3，保留数据 |

## 仍然无法修复的情况（如实写）

如果 403 来自 Key 本身没有该模型权限、地区限制或 CDN/WAF 拦截（例如 Cloudflare 的 "Forbidden" HTML），
应用无法绕过——但现在错误气泡会显示对方给的具体理由，你可以据此换 Key / 换渠道 / 换地址。
